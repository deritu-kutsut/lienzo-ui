## Что создаёт экспорт

Всё записывается в `Assets/EditorGUI` проекта Unity:

| Файл | Назначение |
|---|---|
| `Designs/<Design>.json` | Макет. Импортёр пересобирает prefab каждый раз, когда он меняется. |
| `Editor/EditorGuiImporter.cs` | Собирает prefab с помощью uGUI + TextMeshPro. Меню **Tools › Lienzo UI**. |
| `Prefabs/<Design>.prefab` | Готов к использованию. |
| `UI Toolkit/<Design>.uxml` + `.uss` | Версия для UI Toolkit (UIDocument, PanelSettings 1920×1080 Scale With Screen Size). |
| `Scripts/<Design>OnGUI.cs` | Версия для IMGUI: добавьте его на GameObject. |
| `Scripts/<Design>ViewBase.cs` | Типизированные ссылки и события (генерируется заново). |
| `Scripts/<Design>View.cs` | **Ваша** логика: создаётся один раз и никогда не перезаписывается. |
| `Sprites/`, `Fonts/` | Изображения и шрифты, которые использует макет. |

`<Design>` — это название в PascalCase без диакритики (`Menú principal` → `MenuPrincipal`).

Если какого-то изображения нет, ничего не записывается: экспорт останавливается до изменения проекта и сообщает, какой файл не удалось прочитать.

## Якоря и масштабирование

- Когда ничего не выделено, Инспектор показывает **Canvas Scaler**: опорное разрешение, *match* и фон.
- У каждого элемента есть якоря, пивот и смещения, как у `RectTransform`. Когда опорное разрешение меняется, элементы следуют своим якорям.
- Встроенные шаблоны рассчитаны на 1920×1080; на меньших или вертикальных страницах они равномерно уменьшаются, чтобы уместиться.
- Перед экспортом проверьте макет в режиме **Тест** (F5) на нескольких экранах.

## Компоновки и списки

Контейнер может располагать дочерние элементы по горизонтали, по вертикали или сеткой (как *Layout Groups* в Unity), с промежутками и отступами. ScrollView вычисляет своё содержимое. Порядок в Иерархии — это порядок отрисовки.

## Логика

- **В редакторе**: в режиме проверки каждый элемент может по нажатию выполнять скрипт Rhai (`show("Name")`, `hide`, `toggle`, `set_text`, `set_color`, `move_by`…). Полезно для прототипирования переходов. Изменения, сделанные во время проверки, отбрасываются при выходе из режима проверки и никогда не сохраняются и не экспортируются.
- **В Unity**: `<Design>View` наследуется от `<Design>ViewBase`, с одним полем на каждую кнопку, слайдер, переключатель или поле ввода и методами `On<Element>Click` / `On<Element>Changed` для переопределения.

```csharp
public class AjustesView : AjustesViewBase
{
    protected override void OnBotonVolverClick() => gameObject.SetActive(false);
}
```

Давайте интерактивным элементам уникальные имена: скрипты и `GameObject.Find` находят только первое совпадение. **Проверить** предупреждает о повторяющихся именах.

## Проверить макет

Кнопка **Проверить** (и `--review` в командной строке) проверяет при опорном разрешении:

| Проверка | Правило |
|---|---|
| Размер текста | Не меньше 18 px при 1080p |
| Контраст | WCAG: 4.5:1 или 3:1 для крупного текста (24 px или 18.7 px полужирным); отключённые элементы управления исключены |
| Размер для касания | Кнопки, переключатели, поля ввода и раскрывающиеся списки — не меньше 64 px по короткой стороне при 1080p |
| Страница | Элементы полностью или частично за пределами страницы |
| Имена | Повторяющиеся имена у интерактивных элементов |
| Изображения | Файлы изображений, которых больше нет |

Контраст ниже 2:1, элементы полностью за пределами страницы и отсутствующие изображения — ошибки; остальное — предупреждения.

## Командная строка

```bash
lienzo-ui --templates                                   # выводит список шаблонов (0-12)
lienzo-ui --template 4 --save inventory.editorgui.json
lienzo-ui --open inventory.editorgui.json --review    # код выхода 1, если есть ошибки
lienzo-ui --open inventory.editorgui.json --export "C:/MyGame"   # без окна
lienzo-ui --open inventory.editorgui.json --screenshot capture.png
lienzo-ui --test 1080x2400                             # открывает в режиме проверки с этим экраном
lienzo-ui --tutorial [--pro]                     # принудительно открывает обучение
lienzo-ui --no-tutorial                                 # не открывает его
```

`--save`, `--export` и `--review` не открывают окно: используйте их в скриптах, CI и с [MCP-сервером](MCP.md) (инструмент `review_design`).

Добавьте --dry-run к --export, чтобы вывести каждый файл как new, update, same или remove, ничего не записывая.

export_unity пишет прямо в Assets/EditorGUI того проекта, который укажет ИИ, без каких-либо запросов в редакторе: подтверждение — это подтверждение инструментов вашего MCP-клиента. Попросите ИИ сначала вызвать его с dry_run: true, прочитайте список и только потом экспортируйте по-настоящему.

## Вертикальный макет подробно

Вертикальный макет — это второй вид того же макета (docs/FORMAT.md › PortraitLayout):

- У него своё опорное разрешение, «Вертикальный размер» (по умолчанию 1080 × 1920).
- Элементы без переопределений сохраняют горизонтальный RectTransform и пересчитываются относительно вертикальной страницы: фон на весь экран растягивается, элементы с привязкой справа следуют за правым краем.
- Сохраняется только то, что вы меняете в вертикальном виде, в виде переопределений (позиция, размер, поворот, якоря, видимость, размер шрифта, layout). Правый клик › «Вернуть к горизонтальному» удаляет одно из них.
- Экспорт: JSON содержит переопределения, а сгенерированный скрипт LienzoOrientationLayout применяет их при Screen.width < Screen.height и снова при изменении размера.
- «Удалить вертикальный макет» стирает все переопределения.

Шаблоны поставляются с готовым вертикальным макетом, сохранённым как исключения горизонтального, поэтому «Портрет» сразу показывает макет, рассчитанный на телефоны.

## 9-slice и встроенный пакет

Для рамок, кнопок и панелей, которые растягиваются:

- Выберите Изображение и задайте «9-slice» в «Параметры изображения (Unity)»: границу в пикселях исходного изображения (слева, снизу, справа, сверху), как в Sprite Editor Unity. Экспорт создаёт спрайт 9-slice.
- «Пикселей на единицу»: 100 сохраняет границы в их пиксельном размере, 200 уменьшает их вдвое.
- Встроенный пакет (assets/pack/manifest.json, docs/CONTENT.md) уже задаёт нарезку и пиксели на единицу: рамки 512×512 с нарезкой 96, кнопки 512×192.
- Использование элемента копирует его в вашу библиотеку как pack_<id>.<ext> (скрыт в «Ваши изображения»); экспортёр копирует его в Sprites Unity.
- Шаблоны «HUD пиксельной RPG» и «Главное меню в пикселях» используют пиксельный пакет. Включите Pixel art для фильтра Point.

## Проверка и быстрые исправления

Окно «Проверить» перечисляет ошибки и предупреждения; щёлкните по одному, чтобы выделить элемент. У шести проблем есть кнопка «Исправить» (один шаг отмены):

- Текст меньше минимального размера: увеличивается до минимума.
- Элемент слишком мал для нажатия: увеличивается вокруг центра.
- Элемент частично за пределами страницы: сдвигается внутрь, если помещается.
- Повторяющееся имя: добавляется _2, _3…
- Отсутствующее изображение: ссылка удаляется.
- Низкий контраст: цвет текста затемняется или осветляется.

«Исправить все безопасные проблемы» применяет их за несколько проходов. Для проблем вроде шрифта без нужных символов автоматического исправления нет. Исправления работают и в вертикальном макете. Из командной строки: lienzo-ui --open файл --review (код 1 при ошибках).

## Импорт из Unity: префабы и CLI

Файл › Импорт из Unity… читает префаб uGUI .prefab (текстовый YAML Unity) или Designs/*.json, экспортированный Lienzo UI, и создаёт обычный макет.

- То, что не удалось преобразовать, выводится как предупреждения.
- Если папка проекта Unity найдена, изображения в этой сессии ищутся относительно неё.
- Без окна: lienzo-ui --import-unity Menu.prefab --save Menu.editorgui.json (также с --review и --export).
- Весь проект: lienzo-ui --import-unity-project MyProject --out Imported преобразует все префабы интерфейса. Файлы не перезаписываются (добавляется _2), префабы без интерфейса пропускаются.
- Подробности — в docs/UNITY_IMPORT.md.

## Сообщество: плагины, шрифты и правила

Во вкладке «Сообщество» кнопка «Установить» добавляет общий контент одним щелчком: плагины, шрифты, изображения, шаблоны, элементы и темы.

- Плагин сообщества попадает в папку с именем community-<имя>-<хеш>. Сначала он записывается во временную папку, поэтому прерванная установка никогда не оставляет половину плагина. Он появляется во вкладке «Плагины».
- Его скрипты — те же Rhai: изолированные, без доступа к файлам и сети, с ограничениями по операциям, времени и памяти (docs/PLUGINS.md).
- Установленный шрифт добавляется во вкладку «Текст» и экспортируется в Unity вместе с макетом.
- Загрузки проверяются по опубликованному отпечатку SHA-256; если он не совпадает, ничего не устанавливается.
- Чтобы публиковать, войдите (GitHub или Google), выберите публичное имя и примите правила. Всё проверяется заранее, а контент 18+ нужно помечать. См. docs/TERMS.md, docs/COMMUNITY_GUIDELINES.md и docs/PRIVACY.md.

«Предпросмотр» показывает шрифт с примером текста или команды, экспортёры, файлы и исходный код плагина (только чтение) до установки; ничего не устанавливается, загрузка не засчитывается. «Перевести» отправляет только это описание бесплатному сервису MyMemory, когда вы нажимаете кнопку (docs/PRIVACY.md).

## Автосохранение, восстановление и отмена

- Примерно раз в минуту, пока вы редактируете, весь макет (включая вертикальный) записывается в папку восстановления приложения. Никогда в режиме тестирования. Хранится не более 10 копий.
- При запуске предлагается копия, более новая, чем файл проекта: «Восстановить» или «Отбросить». После обычного сохранения она больше не нужна.
- Отключить можно в «Доступность › Автосохранение».
- История отмены ограничена 200 шагами и примерно 64 МБ. Когда самые старые шаги удаляются, в строке состояния появляется «История сокращена».
- Каждая команда плагина и каждое «Исправить» в окне «Проверить» — один шаг отмены.
